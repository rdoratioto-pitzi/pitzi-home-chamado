Correção da autenticação por usuário

Garantir que, ao fazer login com email e senha, o sistema crie a sessão com o ID real do usuário autenticado, sem reaproveitar sessão ou contexto do Admin.

Validar que o token/sessão contenha apenas os dados do usuário logado (id, nome, email, módulos permitidos), removendo qualquer referência a perfis de outros usuários.
​

Separação entre autenticação e autorização

Manter a autenticação apenas como verificação de credenciais (email + senha) e mover toda a lógica de permissões para uma camada de autorização baseada no perfil do usuário.

Implementar controle de acesso baseado em papéis/módulos (RBAC), em que cada usuário recebe permissões conforme “Usuários e Acessos” e perfil criado na tela de cadastro.

Respeitar módulos habilitados por usuário

Ao autenticar, carregar da base de dados a lista de módulos marcados para aquele usuário na tela “Usuários e Acessos” (Chamados, Projetos, Tarefas, OKRs, Logística, APIs Log, Configurações).
​

No backend, validar em cada rota/endpoint se o usuário tem permissão para o módulo antes de retornar dados ou permitir ações, bloqueando acesso mesmo que a interface tente acessar.

No frontend, exibir apenas os módulos habilitados para o usuário logado (menus laterais, botões e telas) com base nas permissões retornadas pela API, evitando que o layout assuma automaticamente o perfil do Admin.
​

Bug atual: login de usuário assumindo acessos de Admin

Revisar o fluxo de login para verificar se a aplicação está usando credenciais do Admin “hardcoded”, variáveis globais ou sessão compartilhada entre usuários, e remover essa dependência.

Assegurar que, ao trocar de usuário (logout/login), todos os dados de sessão/cache/localStorage sejam limpos, e que um novo token seja gerado somente com as permissões do novo usuário.
​

Focar somente em login por Email e Senha

Desabilitar temporariamente as integrações Google OAuth e Microsoft OAuth na tela de Autenticação e no código (não exibir botões, não aceitar logins por esses provedores).
​

Garantir que o único fluxo válido de autenticação seja: formulário de email e senha, validação segura no backend (senha hasheada com algoritmo robusto como bcrypt/Argon2) e emissão de token/sessão.
