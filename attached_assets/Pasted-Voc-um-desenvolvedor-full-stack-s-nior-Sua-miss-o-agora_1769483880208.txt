Você é um desenvolvedor full‑stack sênior. Sua missão agora é criar o Módulo Tarefas dentro do sistema Renov Home.

1. Objetivo do módulo
Criar um espaço de produtividade pessoal e colaborativa, inspirado em Notion (blocos, páginas, banco de dados de tarefas, templates) e nas interações do Slack (threads, menções, reações, anexos).
​

O módulo deve permitir:

Criar Tarefas para si ou compartilhadas com outros usuários.

Conversar dentro de cada tarefa (comentários em thread, menções, reações).
​

Criar Áreas (workspaces leves) para organizar tarefas, notas e conteúdos, com controle de privacidade (privado ou compartilhado).

Criar templates especiais, começando por Agenda de Reunião / Ata com tópicos, decisões e ações.

2. Conceito de dados
Modelagem base (ajuste com Prisma/TypeScript):

areas

id, name, description, owner_id

visibility: private | shared

created_at, updated_at

area_members

area_id, user_id, role (owner, editor, viewer)

tasks

id, area_id

title, description (rich text / markdown simples)

type: task | meeting_note (para Agenda de Reunião)

status: todo | doing | done | archived

priority: low | medium | high

assignee_id (opcional)

due_date (opcional)

created_by, created_at, updated_at

task_comments (interação ao estilo Slack thread)
​
​

id, task_id, author_id

content (texto rico)

parent_comment_id (para thread/resposta)

created_at

task_reactions

id, comment_id, user_id, emoji

attachments

id, task_id, uploaded_by, file_url, file_name, created_at

templates

id, name, type (meeting_agenda, etc)

structure / default_content (JSON)

4. Fluxos principais
Implementar os seguintes fluxos end‑to‑end (API + UI):

Criar Área

Usuário define nome, descrição e se é privada ou compartilhada.

Se compartilhada, selecionar membros e privilégios (editor/viewer).

Criar Tarefa

Escolher Área.

Definir se é Tarefa simples ou Agenda de Reunião (aplica template automaticamente).

Campos mínimos: título, tipo, status inicial, responsável (opcional), data (opcional).

Colaborar em Tarefa

Adicionar comentários.

Mencionar usuários @.

Iniciar/responder threads.

Adicionar reações com emoji.

Anexar arquivos.

Gerir Tarefas pessoais vs compartilhadas

Usuário consegue filtrar “Minhas Tarefas” (onde é responsável ou criador).

Em Áreas compartilhadas, todos os membros com permissão veem e editam conforme role.

5. API sugerida (REST)
Backend em Node/Express + PostgreSQL/Prisma:

Áreas

GET /api/v1/areas (minhas áreas + compartilhadas)

POST /api/v1/areas

PUT /api/v1/areas/:id

GET /api/v1/areas/:id/tasks

Tarefas

GET /api/v1/tasks?area_id=&status=&assignee_id=

POST /api/v1/tasks

GET /api/v1/tasks/:id

PUT /api/v1/tasks/:id

DELETE /api/v1/tasks/:id

Comentários e reações

GET /api/v1/tasks/:id/comments

POST /api/v1/tasks/:id/comments

POST /api/v1/comments/:id/reactions

DELETE /api/v1/comments/:id/reactions/:reaction_id

Anexos

POST /api/v1/tasks/:id/attachments (upload)

DELETE /api/v1/attachments/:id

Templates

GET /api/v1/templates?type=meeting_agenda

Autorização: somente usuários autenticados; respeitar regras de acesso às Áreas (privada vs compartilhada).
