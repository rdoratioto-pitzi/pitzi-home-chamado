## 💡 Filosofia: "Vibe Coding"

O "Vibe Coding" é a filosofia que guia todas as decisões técnicas e de produto na Renov.

### Princípios Fundamentais

#### 1. **Aprendizado Prático > Teoria Acadêmica**
- Aprender fazendo, errando, iterando
- Valorizar experiência prática sobre certificações
- Experimentar novas tecnologias em projetos reais
- Documentar aprendizados para o time

**Exemplo prático:**  
*"Vamos testar essa lib nova em um módulo pequeno antes de decidir se adotamos no projeto todo."*

#### 2. **Configuração Manual Quando Traz Controle**
- Preferir entender o que está sendo configurado
- Automação total nem sempre é melhor
- Controle > conveniência cega
- Manual hoje, automatizado quando dominarmos

**Exemplo prático:**  
*"Vamos configurar o CI/CD manualmente primeiro para entender cada step, depois criamos templates."*

#### 3. **Soluções Cost-Effective Sempre**
- ROI deve ser claro em toda decisão técnica
- Ferramentas caras só se justificarem economicamente
- Open source prioritário quando possível
- Medir custos de infraestrutura constantemente

**Exemplo prático:**  
*"Migramos de Replit ($20/mês × 5) para GitHub Codespaces (120h grátis/dev) = economia de ~$100/mês"*

#### 4. **Iteração Rápida com Validação**
- MVP funcional > produto perfeito atrasado
- Testar com usuários reais cedo
- Ajustar baseado em feedback, não em suposições
- Releases frequentes > big bang releases

**Exemplo prático:**  
*"Lançar Macgyver AI em beta interna primeiro, coletar feedback do time, ajustar, depois expandir."*

#### 5. **Documentação Viva**
- Documentação que evolui com o código
- Atualizar docs é parte do desenvolvimento
- Docs práticas e objetivas (não academicismo)
- Código legível > documentação extensa

**Exemplo prático:**  
*"Cada PR que muda arquitetura atualiza o /docs/ correspondente antes de merge."*

#### 6. **Pragmatismo Técnico**
- Usar a ferramenta certa para o problema
- Não forçar padrões por modismo
- "Funciona bem" > "É o mais novo framework"
- Technical debt consciente e gerenciado

**Exemplo prático:**  
*"Mantemos JavaScript em partes legacy enquanto migramos gradualmente para TypeScript, sem reescrever tudo de uma vez."*

## 💼 Valores de Desenvolvimento

### 1. **Pragmatismo Técnico**
> *"O que funciona bem é melhor que o que é teoricamente perfeito"*

Escolhemos ferramentas e abordagens baseado em:
- ROI real e mensurável
- Curva de aprendizado do time
- Suporte da comunidade
- Custo total de ownership

### 2. **Transparência Radical**
> *"Comunicação clara > hierarquia rígida"*

- Decisões documentadas publicamente (para o time)
- Erros compartilhados como aprendizado
- Código aberto internamente (todos veem tudo)
- Feedback honesto e construtivo

### 3. **Economia Inteligente**
> *"Gastar bem > gastar pouco"*

- Investir em ferramentas que multiplicam produtividade
- Evitar custos recorrentes desnecessários
- Open source quando possível, pago quando necessário
- Medir e otimizar custos mensalmente

### 4. **Escalabilidade Consciente**
> *"Construir para hoje, preparar para amanhã"*

- Não over-engineer para problemas futuros hipotéticos
- Arquitetura que permite crescimento sem rewrite
- Technical debt gerenciado e pago progressivamente
- Refatoração contínua > refatoração massiva

### 5. **Aprendizado Contínuo**
> *"Time que aprende > time que sabe tudo"*

- Tempo dedicado para estudar novas tecnologias
- Incentivo a experimentação (com limites controlados)
- Compartilhamento de conhecimento interno
- Erros são oportunidades de aprendizado
